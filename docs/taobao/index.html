淘宝用户购物行为项目介绍

概述

本数据集包含了2017年11月25日至2017年12月3日之间，有行为的约一百万随机用户的所有行为（行为包括点击、购买、加购、喜欢）。数据集的组织形式和MovieLens-20M类似，即数据集的每一行表示一条用户行为，由用户ID、商品ID、商品类目ID、行为类型和时间戳组成，并以逗号分隔。

数据范围

字段 类型 描述
用户ID 整数类型 序列化后的用户ID
商品ID 整数类型 序列化后的商品ID
商品类目ID 整数类型 序列化后的商品所属类目ID
行为类型 字符串 枚举类型，包括 ('pv', 'buy', 'cart', 'fav')
时间戳 - 行为发生的时间戳

行为类型 描述
pv 商品详情页PV，等价于点击
buy 商品购买
cart 将商品加入购物车
fav 收藏商品

项目研究目的

本项目观察样本期内的行为结构和时间变化，为后续运营测试提供线索。
商品分析按浏览规模和购买/浏览行为次数比进行分层，用于识别值得进一步测试曝光、推荐或详情页优化的商品。
用户分析按互动商品数、活跃天数和购买行为次数分组，用于比较不同活跃度群体的行为差异，并形成差异化触达假设。

数据清洗

经检查发现原csv文件体量过大，包含一亿条数据，大小高达数GB，对于传统的pandas数据分析会导致电脑内存溢出导致电脑死机。
针对源文件数据量过大的问题，我们最终决定使用在处理大量数据时比较优秀的duckdb来创建数据库，并直接在database中使用SQL语言进行数据清洗。

Python 代码
_ = duckdb.connect(db)

#清除重复值
_.execute("""
    CREATE OR REPLACE TABLE Cleaned AS
    SELECT DISTINCT * FROM Raw
""")

#清除缺失值
_.execute("""
    DELETE FROM Cleaned
    WHERE user_id IS NULL
    OR good_id IS NULL
    OR act IS NULL
    OR ts IS NULL
    OR prop_id IS NULL;
""")

#清除逻辑异常值
_.execute("""
    DELETE FROM Cleaned
    WHERE act NOT IN ('pv','cart','fav','buy')
    OR ts < 1511539200
    OR ts >= 1512316800;
""")

#清理不相关用户
_.execute("""
    DELETE FROM Cleaned
    WHERE user_id NOT IN (SELECT DISTINCT user_id FROM Cleaned WHERE act='pv')
""")

print('数据清洗完成！')
_.close()

数据显示，平台总浏览次数约 8966万次，喜爱次数约 834万次，购买次数约 200万次。收藏约占浏览的 8%，购买约占浏览的 2%，反映出平台拥有较大流量基础，但从浏览到明确购买意向仍存在明显流失。

从经营角度看，主要存在三类优化机会：
一是优化推荐引擎和算法与提高搜索精准度，减少低意向浏览，提高商品与用户需求的匹配程度；
二是优化商品详情页，通过价格优惠、真实评价、物流时效、退换保障等信息降低用户决策成本；
三是加强高意向用户运营，针对收藏、加购及重复浏览用户，通过优惠券、降价提醒和购物车召回促进成交。

建议后续建立“曝光→浏览→收藏→购买→复购”完整漏斗，并按用户、商品、渠道进行拆分，通过A/B测试验证推荐优化、优惠策略和详情页改版的实际效果。因当前数据集没有曝光的相关数据，所以无法分析曝光→浏览的转化效率。

整体而言，平台下一阶段应从单纯追求流量增长，转向提升现有流量的转化效率与商业价值。

        count(CASE WHEN act='fav' THEN user_id END) AS 总收藏次数,

#按各图包含的行为，寻找总互动量最低、最高的连续3小时（允许跨午夜）
hourly = df.set_index('小时').reindex(range(24)).fillna(0)

def mark_hourly_periods(figure, columns):
    totals = hourly[columns].sum(axis=1).tolist()
    windows = [
        sum(totals[(start + offset) % 24] for offset in range(3))
        for start in range(24)
    ]
    # 若多个区间并列，选择起始小时最早的区间
    periods = [
        (min(range(24), key=lambda start: windows[start]), '低谷期', "#919191"),
        (max(range(24), key=lambda start: windows[start]), '高峰期', "#ff9cd8"),
    ]

    for start, label, color in periods:
        segments = [(start - 0.5, min(start + 2.5, 23.5))]
        if start + 2 > 23:
            segments.append((-0.5, start + 2.5 - 24))

        for segment_index, (left, right) in enumerate(segments):
            figure.add_vrect(
                x0=left,
                x1=right,
                fillcolor=color,
                opacity=0.8,
                line_width=0,
                layer='below',
                annotation_text=label if segment_index == 0 else None,
                annotation_position='top left',
                annotation_font_color='#555555'
            )

    figure.update_layout(plot_bgcolor='white', paper_bgcolor='white')
    figure.update_xaxes(
        range=[-0.5, 23.5],
        tickmode='linear',
        tick0=0,
        dtick=1,
        showgrid=False,
        zeroline=False
    )
    figure.update_yaxes(showgrid=False, zeroline=False)

# 固定行为颜色；同一小时内的所有行为按互动总量使用相同的明度强度
behavior_colors = {
    '浏览次数': '#3978d7',
    '收藏次数': '#f4c95d',
    '购物车次数': '#f28e2b',
    '购买次数': '#d9485f'
}

def get_hourly_colors(columns, base_color):
    totals = hourly[columns].sum(axis=1)
    value_range = totals.max() - totals.min()
    intensity = (totals - totals.min()) / value_range if value_range else totals * 0 + 1
    alpha = 0.35 + intensity * 0.65
    red, green, blue = tuple(int(base_color[index:index + 2], 16) for index in (1, 3, 5))
    return [f'rgba({red}, {green}, {blue}, {value:.3f})' for value in alpha]

def build_hourly_bar(name, column, columns):
    return go.Bar(
        name=name,
        x=n,
        y=hourly[column],
        marker=dict(
            color=get_hourly_colors(columns, behavior_colors[name]),
            line=dict(color='rgba(255, 255, 255, 0.95)', width=1.1)
        )
    )

从小时分布看，用户行为呈现明显的昼夜周期特征。22点后互动量快速下降，3—5点为全天低谷；6点后逐步回升，10—18点保持较稳定的活跃水平；晚间进一步增长，20—22点进入流量高峰，21点整体互动量最高。
从购买与浏览行为次数比看，全时段总体水平约为 2.23%。其中10—17点明显高于或接近整体水平，10—12点表现最佳，峰值接近3%；20—22点虽然浏览、收藏和购买规模最大，但购买/浏览次数比反而回落至约2%左右。这表明流量高峰并不等于转化效率高峰。
运营上建议采取“白天抓流量、晚间抓转化”策略：10—16点重点强化核心商品曝光、直播及内容营销；20—22点投放限时优惠、加购召回和高转化商品，并通过个性化推荐承接高流量。同时减少凌晨低效时段的营销投入。
需要注意，上述比例仍属于行为次数比，不能直接等同于同一用户路径下的真实转化率，且所实行的策略效果仍需A|B实验检验验证。

根据以上所有图表进行分析，一般而言，每周周末的晚上八点到十点是该周的流量黄金时段，最适合大规模铺设营销资源，实现流量效应的利益最大化；而每周工作日的凌晨时段是该周的流量低谷期，应减少营销投入，节约成本。
该结论仅结合这数天的数据进行分析，不能严格当作长期的流量规律，关于长期规律仍需未来更多数据作为理论支撑。

商品价值分析

按照商品汇总其pv,cart,fav,buy的数量创建两个新的VIEW，分别按照商品id和商品类目id汇总分析。
定义一个新的数据为like，其值为喜爱或购买某商品的独立用户数。
清除掉部分访问极少的商品(pv<5000)以防止极端值影响结果真实性。

#构建数据库
_ = duckdb.connect(db)

_.execute("""
    CREATE OR REPLACE VIEW Good_Funnel AS
    WITH matric AS
    (
        SELECT
            good_id,
            count(DISTINCT CASE WHEN act = 'pv' THEN user_id END) AS pv_cnt,
            count(DISTINCT CASE WHEN act IN ('fav', 'cart') THEN user_id END) AS like_cnt,
            count(DISTINCT CASE WHEN act = 'buy' THEN user_id END) AS buy_cnt
        FROM
            Cleaned
        GROUP BY
            good_id
        HAVING
            pv_cnt > 5000
    )
    SELECT
        good_id AS 商品id,
        pv_cnt AS 独立浏览次数,
        like_cnt AS 独立喜爱次数,
        buy_cnt AS 独立购买次数,
        round(like_cnt/pv_cnt*100,2) AS 浏览转喜爱率,
        round(buy_cnt/like_cnt*100,2) AS 喜爱转购买率,
        round(buy_cnt/pv_cnt*100,2) AS 浏览转购买率
    FROM
        matric
    ORDER BY
        浏览转购买率 DESC
""")

_.execute("""
    CREATE OR REPLACE VIEW Prop_Funnel AS
    WITH matric AS
    (
        SELECT
            prop_id,
            count(DISTINCT CASE WHEN act = 'pv' THEN user_id END) AS pv_cnt,
            count(DISTINCT CASE WHEN act IN ('fav', 'cart') THEN user_id END) AS like_cnt,
            count(DISTINCT CASE WHEN act = 'buy' THEN user_id END) AS buy_cnt
        FROM

            prop_id

用户价值分析

当前数据包含用户、商品、行为类型和互动时间，但缺少订单金额，因此不能完整构建包含M（Money）的传统RFM模型。
针对此，本项目使用用户在样本期内发生互动的不同商品数、活跃天数和购买行为次数作为特征，通过K-Means进行探索性分群。其中，活跃天数定义为用户在样本期内发生过至少一次行为的不同自然日数量。
分群结果反映的是这9天内的行为差异，不等同于用户的长期价值。

浏览商品数和购买次数具有明显长尾特征，因此在标准化前使用 log1p 降低极端值对欧氏距离的影响。内部质量指标显示 K=2 的轮廓系数为 0.360，高于 K=3 的 0.323；Calinski–Harabasz 指数和 Davies–Bouldin 指数也略偏向 K=2。若只追求几何分离度，两类更合适。
本项目保留 K=3，是为了将互动范围同样较广、但购买行为频次明显不同的两组用户分开。多随机种子检验的 ARI 均为 1.000，说明这次抽样中结果对初始化稳定；稳定不等于预测有效，也不证明 K=3 唯一正确。

项目总结

本项目基于淘宝公开用户行为数据，对2017年11月25日至12月3日约98.8万名用户、超过1亿条浏览、收藏、加购和购买记录进行了分析。面对数GB规模的原始数据，我没有直接使用Pandas全量加载，而是通过DuckDB建立本地分析数据库，使用SQL完成数据清洗、时间特征提取和指标聚合，再结合Plotly与K-Means完成可视化和用户分群。这一过程让我实践了从大规模数据处理、指标设计到业务解释的完整分析流程。

从平台整体行为结构看，浏览行为占据绝大多数，基数十分庞大，但收藏与加购行为次数合计约为浏览次数的8%，购买行为次数约为浏览次数的2%，说明用户从浏览到表达明确购买意向之间存在较大的数量差距。由于这些指标是不同类型行为的汇总次数比，不能直接视为同一用户购物路径上的严格转化率，因此我将推荐优化、分层优惠触达和收藏夹信息增强作为待验证的运营假设，并建议通过路径级漏斗和A/B测试评估实际效果。

小时维度的分析显示，用户行为具有明显的昼夜规律：3—5点是互动低谷，20—22点是互动高峰，其中21点的总体互动量最高。但流量高峰与购买行为效率高峰并不完全重合，浏览与购买行为次数比在10—12点表现较高，晚间流量高峰时则回落至总体水平附近。因此，可以分别将日间高效率时段和晚间高流量时段用于测试不同运营方案：前者侧重重点商品曝光、直播内容和流量承接，后者侧重优惠提醒和购买决策促进。

在商品价值分析中，我筛选独立浏览人数超过5,000的商品和类目，根据浏览量与浏览—购买行为次数比构建四象限模型，用于识别高流量高表现、低流量高表现、高流量低表现和低流量低表现的商品。该模型可以帮助提出差异化的商品运营方向，例如为潜力商品测试曝光提升，为高流量低表现商品检查推荐人群匹配度和详情页质量。相关建议属于观察性分析产生的业务假设，仍需通过实验数据验证。

在用户价值分析中，由于数据缺少订单金额，无法完整使用传统RFM模型，因此我选取互动商品数、活跃天数和购买行为次数作为聚类特征。其中，活跃天数按用户在样本期内发生行为的不同自然日数量计算。针对计数特征的长尾分布，我先进行对数变换和标准化，再综合SSE、轮廓系数、Calinski–Harabasz指数、Davies–Bouldin指数及多随机种子稳定性检验选择K值，并将三类用户解释为低互动、高互动低购买和高互动高购买群体。该分群用于形成差异化运营假设，不代表长期用户价值。

这个项目不仅展示了我处理亿级行为数据、编写SQL、构建可视化和完成用户分群的能力，也体现了我对指标口径和分析边界的重视。当前数据只有9天，且缺少订单金额、商品属性和长期留存信息，因此结论主要反映样本期内的行为特征，不能直接外推为长期规律、真实订单价值或因果关系。后续仍需扩展观察窗口，并通过A/B测试、长期留存和金额指标验证分析形成的运营假设。

from pathlib import Path

def append_metrics(records, data, module, level, dimension_columns, metric_columns, source, note):
    for _, row in data.iterrows():
        dimension = '｜'.join(f'{column}={row[column]}' for column in dimension_columns)
        for metric in metric_columns:
            value = row[metric]
            if pd.notna(value):
                if metric in ['SSE', '轮廓系数', 'Calinski-Harabasz指数', 'Davies-Bouldin指数', '与基准结果的ARI']:
                    unit = '无量纲'
                else:
                    unit = '人' if metric == '总用户数' or metric == '用户数' else ('%' if '率' in metric or '比' in metric else ('天' if metric == '样本天数' or metric == '活跃天数' else ('种' if '商品数' in metric else '次')))
                records.append({
                    '模块': module,
                    '分析层级': level,
                    '维度': dimension,
                    '指标': metric,
                    '数值': value,
                    '单位': unit,
                    '数据来源': source,
                    '口径说明': note
                })

# 从既有聚合视图读取宏观、时间、商品与类目结果
_ = duckdb.connect(db)
macro_export = _.execute('SELECT * FROM macro').fetchdf()
daily_export = _.execute("""
    SELECT
        CAST(时间 AS DATE) AS 日期,
        count(CASE WHEN act='pv' THEN user_id END) AS 总浏览次数,
        count(CASE WHEN act='fav' THEN user_id END) AS 总收藏次数,
        count(CASE WHEN act='cart' THEN user_id END) AS 总购物车次数,
        count(CASE WHEN act='buy' THEN user_id END) AS 总购买次数,
        round(count(CASE WHEN act='buy' THEN user_id END) * 100.0 / NULLIF(count(CASE WHEN act='pv' THEN user_id END), 0), 2) AS 浏览与购买行为次数比
    FROM vCleaned
    GROUP BY 1
    ORDER BY 1
""").fetchdf()
weekday_export = _.execute("""
    WITH daily AS (
        SELECT
            CAST(时间 AS DATE) AS 日期,
            星期,
            count(CASE WHEN act='pv' THEN user_id END) AS 总浏览次数,
            count(CASE WHEN act='fav' THEN user_id END) AS 总收藏次数,
            count(CASE WHEN act='cart' THEN user_id END) AS 总购物车次数,
            count(CASE WHEN act='buy' THEN user_id END) AS 总购买次数
        FROM vCleaned
        GROUP BY 1, 2
    )
    SELECT
        星期,
        count(*) AS 样本天数,
        avg(总浏览次数) AS 日均浏览次数,
        avg(总收藏次数) AS 日均收藏次数,
        avg(总购物车次数) AS 日均购物车次数,
        avg(总购买次数) AS 日均购买次数,
        round(sum(总购买次数) * 100.0 / NULLIF(sum(总浏览次数), 0), 2) AS 浏览与购买行为次数比
    FROM daily
    GROUP BY 1
    ORDER BY 1
""").fetchdf()
hour_export = _.execute("""
    SELECT
        小时,
        sum(总浏览次数) AS 总浏览次数,
        sum(总收藏次数) AS 总收藏次数,
        sum(总购物车次数) AS 总购物车次数,
        sum(总购买次数) AS 总购买次数,
        round(sum(总购买次数) * 100.0 / NULLIF(sum(总浏览次数), 0), 2) AS 浏览与购买行为次数比
    FROM Tmacro
    GROUP BY 1
    ORDER BY 1
""").fetchdf()
good_export = _.execute('SELECT * FROM Good_Funnel').fetchdf()
